# 数据与隐私

这份文档写清楚三件事：什么数据会离开手机、它在服务器上活多久、怎么让它一个字节都不出去。

先说结论：**SIM 卡的国家码、运营商名称、保存的覆盖方案，全部只写在本机的应用私有目录里，从不上传。** 会离开手机的只有下面那几条设备元数据，而且只在构建时配了后台地址的前提下才会发生。

## 谁会有联网行为

| 构建 | 联网行为 |
| --- | --- |
| GitHub Releases 上的安装包 | 检查更新（读 GitHub）；我自建后台的公告与匿名统计 |
| 自己编译、`HUB_BASE_URL` 留空 | 只有检查更新（读 GitHub）。公告、更新推送、统计一个请求都不发 |
| fork 后指向自己的服务器 | 只连 fork 者那台服务器 |

`HUB_BASE_URL` 是构建期字段（`app/build.gradle.kts` 里的 `hubBaseUrl` 属性）。留空时，公告位、更新弹窗里的后台字段、设置页的统计开关**整排都不出现**，不是「出现了但功能是关的」。

## 上传了什么

只有 `POST /api/v1/ping.php` 这一条请求携带设备信息，一天最多一条：

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| 匿名设备 ID | 本机首次运行时随机生成的 32 位十六进制数 | 去重，算出「今天有多少台设备在用」 |
| 机型 | `Build.MANUFACTURER` + `Build.MODEL` | 机型分布。哪些定制系统禁用了接口，只有这个能看出来 |
| Android 版本 | `Build.VERSION.SDK_INT` | 同上，判断该优先适配哪一代系统 |
| 应用版本 | versionName / versionCode | 旧版本还占多少，决定要不要提示重要更新 |
| 界面语言 | `zh` / `en` | 公告和更新说明该发哪一份 |

**没有**：手机号、IMSI、ICCID、序列号、SIM 卡运营商、你填的国家码或自定义名称、保存/还原的具体内容、位置、账号、广告标识符（`AdvertisingId` 这个依赖根本不在包里）。设备 ID 与上面任何字段之间没有可反推的关系——它是一次性随机数，不是从硬件标识算出来的。

`GET /api/v1/bootstrap.php` 只带语言和应用版本两个查询参数，不带任何设备标识；它的内容对所有设备都一样，所以也不做设备级缓存。

## 存在服务器上多久

| 数据 | 保留期 | 到期处理 |
| --- | --- | --- |
| 事件记录 | 45 天 | 按天分块删除 |
| 每日汇总（活跃数、请求数、字节数） | 400 天 | 同上 |
| 设备行（机型、系统版本、最后活跃日） | 365 天不活跃后删除 | 删除时重建机型与版本的累计数 |

清理不依赖主机的定时任务（这台虚拟主机给不了可靠的 cron），由写路径按请求计数触发，加上一个随机兜底，保证低流量日子也能扫到。管理端另有手动按钮。

设备 ID 是这台服务器上留存最久的标识，所以它对应的那一行一年后必然消失。它从来没有和任何非元数据的东西一起存过。

## 怎么关掉

**设置 → 「关于」分组里的「共享匿名使用统计」**，关掉以后一条 POST 都不发（启动日志里会写明是被开关挡住的，而不是没到间隔）。这个开关只影响上报，公告和更新提示照常——那两条走的是另一条不带设备 ID 的请求。

更彻底的办法是不装我的包，自己编译一个 `HUB_BASE_URL` 留空的版本：那条链路上一个字节都不会出手机。

后台侧还有一个总熔断（`poll_on=0`），我可以在流量超预算时把所有客户端的上报停掉，不用发版。

## 为什么这句话改了

早期版本里写过「除检查更新外不发任何网络请求」。加上自建后台之后它不再成立，所以删掉了。现在准确的表述是：

> 不申请任何运行时权限；SIM 相关数据只存本机；网络请求只有你主动点「检查更新」时那一次，配了自建后台地址的构建才会每天拉公告、上报一条匿名统计。

接口本身在 [api-contract.md](api-contract.md) 里完整公开，包括字段名和判定规则。后台代码不开源，但它对客户端做的每一件事都由那份文档约束。
