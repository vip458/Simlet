# Simlet 后台接口契约

这份文档是我自己那台后台（不开源）和 Simlet 客户端之间唯一的边界。它放在开源仓库里，是因为**真源应该在能看到客户端的那一侧**：任何人 fork 这个仓库，照着这份文档就能写一个自己的后台把客户端接走；我的后台也照这份文档实现，两边不一致时以这份文档为准。

后台代码一行都不会进这个仓库，这个仓库的代码也不依赖后台存在。`HUB_BASE_URL` 留空（fork 和自己编译的默认值）时，下面两个请求一个都不会发。

## 通用约定

- **基地址是一个目录前缀**，比如 `https://example.com/simlet-api`。客户端自己拼后面的路径，所以换域名、换子目录都不用重新出包。只接受 `https`；`http` 只在主机是 `127.0.0.1` / `localhost` 时放行，留给本机调试。
- **不带 Cookie、不带 Authorization、不带任何自定义头**。两个端点都是匿名请求。
- 客户端会带 `Accept-Encoding: gzip`，服务端能压就压；响应体上限 1500 字节（gzip 前），超了服务端会自己削，削完还超就只保留更新通道。
- **字段只加不改不删**。要动语义就 bump 顶层 `v` 并开新路径。客户端一律用 `optString` / `optInt` 带默认值读，遇到不认识的字段直接忽略——老版本客户端必须能活在新后台下面。
- 语言只有两档：`zh` 和 `en`，其它一律按 `zh` 取。这条规则两边各写了一遍（客户端 `HubRules.queryLang`、服务端 `Http::lang`），必须一致，否则德语用户会在服务端拿到中文公告、在本地按英文解释它。

## `GET /api/v1/bootstrap.php`

启动时问一次：有没有公告、有没有新版本、多久再问一次。

### 请求参数

全部可选，全部只影响日志和缓存键，**不影响内容**：

| 参数 | 含义 |
| --- | --- |
| `lang` | `zh` / `en` |
| `vn` | 客户端 versionName，只进日志 |
| `vc` | 客户端 versionCode，只进日志 |

内容不随设备变化是这条接口最重要的设计：灰度、版本区间、强制标记全部作为**规则字段**下发，由客户端本地判定。因此全局一个 ETag，任何中间缓存（包括将来套的 CDN）都能直接存下来复用。如果把 `vc` 写进 ETag，缓存命中率会掉到接近零，那 5GB 月额度第一个月就能用完。

### 响应

```json
{"v":1,"g":23,
 "notice":{"id":12,"lv":"alert","ti":"v1.0.3 已发布","bd":"修复无法识别sim卡问题","ur":"https://..."},
 "rel":{"nm":"1.0.3","cd":4,"ro":35,"mi":0,"ma":3,"fc":0,"bk":"v4",
        "pg":"https://github.com/vip458/Simlet/releases/tag/v1.0.3",
        "ap":"https://github.com/vip458/Simlet/releases/download/v1.0.3/app-release.apk",
        "sz":1438720,"mn":"夸克网盘","mu":"https://pan.quark.cn/s/...","mk":"提取码 8k2d",
        "nt":"1. 修复读卡"},
 "pol":{"bm":24,"rp":24,"on":1}}
```

| 字段 | 含义 |
| --- | --- |
| `v` | 契约版本，当前 1 |
| `g` | 配置代次。后台任何一次改动都会 bump 它，全员 ETag 失效重取 |
| `notice` | 没有在线公告时为 `null` |
| `notice.lv` | `info`（默认，界面上不带颜色）/ `warn` / `alert` |
| `notice.bd` / `notice.ur` | 空字符串时整个键不发，省字节 |
| `rel` | 没有在线发布时为 `null` |
| `pol.bm` | 多少小时可以再问一次（客户端钳制在 1–720） |
| `pol.rp` | 多少小时可以再上报一次 |
| `pol.on` | 采集总开关，`0` 时客户端连 POST 都不发 |

`rel` 的触发条件语义（判定在 `HubRules.updateWanted`）：

| 字段 | 判定 |
| --- | --- |
| `cd` | 只有 `本机 versionCode < cd` 才算有更新 |
| `mi` / `ma` | 版本区间，`0` 表示该端不限；区间外不弹 |
| `ro` | 灰度百分比 0–100 |
| `bk` | 分桶盐。换一个盐 = 同一个版本号重投另一批设备 |
| `fc` | 只影响界面（首页顶部多一条提示行），**不做阻塞式强更** |
| `nt` | 更新说明，界面上按行显示 |
| `mn` / `mu` / `mk` | 网盘镜像的名字、地址、提取码。只是多一个按钮，点了复制提取码并交给系统浏览器，应用内不下载任何东西 |

安装包权威源永远是 GitHub Releases（`pg` / `ap`）。后台不存 APK——包体 1.37MB，5GB 月额度只够约 3700 次下载。

### 缓存

```
Cache-Control: public, max-age=min(10800, bm*3600), must-revalidate
ETag: "<md5(gen|lang)>"
Vary: Accept-Encoding
```

命中 `If-None-Match` 直接回 304、零字节正文。客户端把 304 当成「配置仍然有效」，只把确认时间往前推。

### 时间闸门

客户端用**上次尝试**（不是上次成功）的时间做闸门。后台宕了的时候，每次启动都重试只会让弱网用户多白等一个连接超时。拉取失败完全静默：不上屏、不提示、不重试。

## `POST /api/v1/ping.php`

每天一条启动上报。`application/x-www-form-urlencoded`。

| 键 | 含义 | 服务端处理 |
| --- | --- | --- |
| `d` | 匿名设备 ID，本机首次运行时随机生成的 32 位十六进制 | 必须匹配 `^[0-9a-f]{32}$`，否则丢弃 |
| `m` | `Build.MODEL` | 截断到 40 字符 |
| `o` | `Build.MANUFACTURER` | 截断到 40 字符，和 `m` 拼成机型名 |
| `s` | `Build.VERSION.SDK_INT` | 只接受 21–60 |
| `v` | versionName | 截断到 20 字符 |
| `c` | versionCode | 上限 = 已发布的最大 versionCode + 1 |
| `l` | `zh` / `en` | 其它按 `zh` |
| `e` | 事件名，当前只有 `boot` | 不在白名单里就按空处理 |

**响应恒为 204 No Content**，包括校验失败和被限流——不给探测者任何「这个字段错了」的反馈，失败只记进服务端的 `dropped` 计数。

设备 ID 只在这条请求里出现。它不参与灰度判定（灰度用的是另一个永不上送的本机种子），所以关掉统计不会影响更新提示。

### 为什么没有签名

客户端在 Apache-2.0 的公开仓库里，任何内置密钥都能被提出来，伪造这条 POST 的成本约等于零。所以不假装防得住，只做四件事：字段白名单、按 IP 的文件计数限流、可疑标记（默认不进统计）、以及一个服务端就能拨的熔断开关。真正的天花板是主机的「超额停用」，不是代码。

## 关掉统计

设置 → 权限与数据 上面那一行「共享匿名使用统计」。关掉以后这条 POST 一个都不发；这一行本身只在构建时配了后台地址才会出现。详见 [privacy.md](privacy.md)。

## 后台不可用时

`bootstrap` 失败 → 公告位不显示，检查更新自动回落到直接读 GitHub Releases。功能不退化到不可用，也不会有任何报错上屏。
