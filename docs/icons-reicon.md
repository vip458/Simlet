# Simlet 图标规范 · Reicon

> 全应用只有一处图标来源：`app/src/main/java/dev/reicon/`（vendored 的 Reicon 子集）。
> `res/drawable` 里不再有矢量图标，`material-icons-extended` 依赖已从 `app/build.gradle.kts` 移除。
>
> `res/drawable*` 下只剩两个资源：`drawable/ic_launcher_foreground.xml`（启动图标前景，矢量）与
> `drawable-nodpi/wechat_qrcode.jpg`（公众号二维码原图，258×258，由运营方提供，不是图标）。
> 二维码放 `nodpi` 是为了不让系统按屏幕密度重采样——它一旦插值糊了就扫不出来；
> 显示尺寸由 `WechatSheet` 的 180dp 决定，且**不裁圆角**（四角是定位点，clip 会吃掉模块）。

## 1. 为什么是 vendored，而不是加依赖

上游 Compose 产物当时不可用，三条实测：

- Maven Central 上没有 `reicon-compose`；
- JitPack 上所有 tag 的构建状态是 `Error`；
- README 给的坐标直接 404，且它的 `api` 依赖 `compose-bom 2026.04.01`，
  会强制本项目从 `2024.12.01` 升一个 Compose 大版本。

所以改用上游自带的生成器 `packages/reicon-compose/tool/build_kotlin.py`，
把 ImageVector 源码抽进仓库。换来的是：零新增依赖、离线可构建、图标改动是可读的 git diff。

代价是图标不再随上游自动更新 —— 这是刻意的：一套 UI 的图标描边宽度必须锁死，
上游哪天改一笔，界面就整体变形，而我们没有每天回归界面的预算。

## 2. 命名规则

| 项 | 规则 | 例 |
| --- | --- | --- |
| 上游名 | kebab-case | `chevron-expand-y` |
| 文件名 / object 名 | 上游名去连字符转 PascalCase | `ChevronExpandY.kt` / `object ChevronExpandY` |
| 引用 | `import dev.reicon.ChevronExpandY` | — |
| 使用 | `ChevronExpandY.Outline` | — |

- **一律用 `.Outline`**。`.Filled` 由生成器一并产出但当前 0 处使用；要用它必须先在本文件加一条
  「什么场景下允许实心」的规则，不允许在单个页面里破例。
- 包名保持上游的 `dev.reicon`，这样重跑生成器是原地覆盖，不需要改任何 import。
- 文件头写着 `Auto-generated by tool/build_kotlin.py - do not edit.`，手改会在下次重跑时被冲掉。

## 3. 尺寸档位

只有这四档，新增档位要先想清楚为什么现有四档不够。

| 档 | dp | 用在哪 | 定义处 |
| --- | --- | --- | --- |
| 行内图标 | 20 | `SettingRow` 左侧那一列 | `ui/component/Group.kt` 的 `IconSize` |
| 行尾箭头 | 16 | `›` 与上下选择箭头 | `SettingRow` 内 |
| 顶栏动作 | 24 | 刷新 / 帮助 / 设置 | `IconButton` 默认值 |
| 说明性主图 | 48 | 环境自检顶部 | `ui/screen/SetupScreen.kt` |

另有四支嵌在别人的版式里，不算档位：搜索框前导 18dp、弹层分组折叠 14dp、
「重新检测」按钮内 18dp、「复制名称」按钮内 18dp。

矢量本身是 24×24 viewport，缩到 14dp 仍不糊；不要传带小数的 dp，会落在半像素上。

## 4. 着色

图标不参与配色体系，只有两档灰：

- **`onSurface`**：行内图标、顶栏动作、说明性主图。明暗模式自动翻。
- **`outline`**：行尾箭头、折叠箭头。比正文弱一档，表示「这是个控件」而不是「这是个信息」。

禁止：

- 彩色图标 —— 整套 UI 唯一的彩色是 `secondary` 绿，只出现在徽章与状态点；
- 硬编码 `Color(0x...)` 当 tint；
- 用 `Modifier.alpha()` 表达禁用 —— 走 `SettingRow(enabled = false)`，
  它会把文字和图标一起降到 `outline`。

## 5. 新增图标的流程

1. 在 <https://reicon.dev/icons> 浏览，记下 kebab 名；
2. 把名字加进 `tools/gen-icons.py` 的 `ICONS` 列表，后面注释写清用在哪一行；
3. `python tools/gen-icons.py`
   —— 脚本钉死了上游提交 `fe69753`，先清空旧图标再全量生成，所以从列表里删掉的名字不会留成孤儿文件；
4. 构建（本仓库的 `gradlew` 脚本残缺，直连 wrapper jar）：
   ```
   java -classpath gradle/wrapper/gradle-wrapper.jar org.gradle.wrapper.GradleWrapperMain :app:assembleRelease
   ```
5. 装机走查第 7 节那张表，确认新图标与相邻图标描边视觉等粗。

名字写错时脚本会直接退出并列出「上游没有这些图标名」，不会静默生成半套。

小屏一档（临时把测试机改成 720×1440 / 300dpi ≈ 384dp 宽，走完即恢复原分辨率与密度）：
首页、设置、运营商弹层均无截断、无错位；顶栏标题左对齐后与右侧三个动作图标不相撞。
横屏一张是设备当时正好躺着顺手截的，版式同样成立。

走查中改掉的问题：

- 弹层底色仍是 Material3 默认的紫调 `surfaceContainerLow`（`#F7F2FA`）——
  `lightColorScheme()` 没传的角色会用默认值，与「蓝色系归零」冲突，已把整组
  `surfaceContainer*` / `inverse*` 按实测灰阶补齐；
- 无图标的行（如「当前版本」）左缘比同卡其它行少 36dp，和同卡的带图标行错开一列 ——
  `SettingRow` 现在为空的图标位照样留白，统一对齐到文字列；
- 首页顶栏标题居中时贴着右侧动作图标 —— 无返回键的屏改为左对齐到内容列，
  有返回键的屏保持居中（左右各一组控件，居中才成立）。
